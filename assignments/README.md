# assignments — 연구실(SIBL) 과제 [과제축]

SIBL 연구실 대학원생이 내주는 **과제와 그 수행 결과물**을 담는 폴더.

이 저장소의 다른 축과 성격이 다르다. `study-log/`는 "내가 그날 뭘 공부했나"이고
`docs/`는 "내 진도가 어디까지인가"이고 `notes/`는 "그 개념이 무엇인가"인데,
여기는 **"밖에서 요구받은 일을 어떻게 완수했나"** 다.
받는 사람(평가자)이 있고, **완료 기준이 내가 아니라 과제 문서에 적혀 있다**는 점이 결정적 차이다.

## 폴더 규칙

**하나의 과제 = 하나의 폴더.** 폴더명은 날짜가 아니라 **과제 주제**로 짓는다.
과제는 며칠에 걸쳐 진행되므로 특정 날짜에 묶이지 않고, 나중에 찾을 때도
"9월 3일에 뭐 했더라"가 아니라 **"그 카메라 과제"** 로 찾게 되기 때문이다.
(날짜 기준으로 찾고 싶으면 `study-log/`를 본다 — 그쪽이 시간축이다.)

```
assignments/
├── README.md                    ← 지금 이 파일 (과제 목록 안내판)
└── <과제-주제>/
    ├── practice-log.md              수행 기록 본문
    └── images/                      기록에 삽입되는 스크린샷 (상대경로 images/파일명)
```

- **`README.md`라는 이름은 안내판에만 쓴다.** 본문 문서는 `practice-log.md`처럼 제 이름을 갖는다.
  (한때 수행 기록을 `README.md`로 뒀다가, 대문·인덱스·본문이 전부 같은 이름이 되어 되돌림)
- 과제가 끝나도 기록은 **사후에 고치지 않는다.** 그때 그렇게 알았다는 것 자체가 기록이다.
  (저장소 전체 규칙 — `CLAUDE.md` §7)

## 진도 체크리스트와의 관계

R2R 강좌 진도(`docs/ros2-r2r-checklist.md`)와 과제는 **별개로 관리한다.**
과제로 다룬 범위가 강좌 진도와 겹치더라도, **강의 영상을 보지 않았으면 체크하지 않는다.**
겹치는 구간이 생기면 체크리스트 쪽에 "과제로 먼저 체험함" 주석을 달아 연결해둔다.
(실제로 ROS 2 기초 실습 과제가 R2R 묶음 3과 그대로 겹쳐서, 그렇게 처리해뒀다.)
