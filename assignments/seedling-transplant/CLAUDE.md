# 수경재배 모종 이식 과제 — Claude 작업 규칙

이 폴더(`assignments/seedling-transplant/`)를 다룰 때 루트 `CLAUDE.md`에 더해 따른다.
둘이 부딪히면 멈추고 사용자에게 묻는다.

## 1. 문서 지도

| 문서 | 무엇 | 고치는 법 |
|---|---|---|
| `problem-definition.md` | 무엇을 풀까 — 대상 · 장비 · 성공 기준 | 문제 자체가 바뀔 때만. 맨 아래 변경 이력 한 줄 |
| `plan.md` | 어떤 순서로 시험할까 — P0 ~ P5, 대기 W1 ~ W7, 결정 표 | plan §2 규칙 |
| `checklist.md` | 할 일 — plan ID 그대로, 항목마다 ✔ 끝 기준 | checklist "바꾸는 규칙" |
| `test-seedlings.md` | 시험 재료(모종) 사정 · 재배 기준 | 답을 받으면 갱신 + 변경 이력 |
| `practice-log.md` | 날짜별 시험 기록 | **추가만** (아래 §3). 없으면 첫 기록 때 만든다 |
| `code/` | 스크립트 (예: `code/gripper/`) | — |
| `images/` | 사진 `YYYY-MM-DD-설명.png` | — |

같은 사실은 한 곳에만 쓴다. **판정 기준의 원본은 plan, 진도의 원본은 checklist 체크박스**다.

## 2. 항목 하나 진행하기 — "P1-1 하자" / "다음 항목 하자"

1. **고르기** — ID를 말하면 그 항목. 안 말하면 checklist "전체 한눈에"에서 지금 할 수 있는 후보 2~3개를 보여주고 묻는다
2. **끝 기준 먼저** — 그 항목의 ✔ 끝과 🔒(기다리는 것)를 말한다. 🔒가 안 풀렸으면 멈춘다
3. **한 번에 한 단계** — 세부 순서대로. 명령 하나 → 결과 확인 → 다음. 명령 설명은 루트 §5 방식(뜻 → 옵션 → 출력 해석)
4. **몸으로 보는 것은 사용자에게** — 움직였나, 눌렸나, 몇 mm인가는 사용자가 본 값으로 적는다. 추정해서 채우지 않는다
5. **기록** — `practice-log.md`에 아래 §3 형식으로
6. **체크** — ✔ 끝을 만족했을 때만 `[x]`. 끝낸 세부도 체크하고, "전체 한눈에" 표의 "끝" 숫자를 고친다. 실패면 체크하지 않고 원인 가설과 다음 시도를 적는다
7. **커밋을 제안하고 멈춘다** — 기록 + 체크를 한 커밋으로. 다음 항목은 사용자가 말할 때 시작한다

- 같은 방법이 2번 실패하면 3번째 시도 전에 멈추고 원인 가설부터 세운다

## 3. 기록 형식 — `practice-log.md`

```markdown
## 2026-09-30

### P1-1 ToolkitRC 출력 전압 측정 — ✅ 통과
- 한 일:
- 명령 · 설정:
- 결과: (수치 · 출력 요약)
- 판정: ✔ 끝 기준 대비 — 통과 / 실패 / 보류
- 사진: `images/2026-09-30-설명.png`
- 다음:
```

- 날짜 아래에 시험 ID로 묶는다. 한 항목을 며칠에 걸쳐 하면 날짜마다 같은 ID로 이어 적는다
- 과거 기록은 고치지 않는다. 정정은 새 항목으로 (루트 §7)

## 4. 바뀔 때 — 어디부터 고치나

| 바뀐 것 | 고칠 곳 |
|---|---|
| 세부 순서 | checklist만 |
| 시험(굵은 항목) · 단계 · 순서 | plan §1 변경 이력 → plan 본문 → checklist. 한 커밋 |
| 시험으로 정해진 값 | plan §5 결정 표 (+ plan §3 상태) — 버전은 안 올린다 |
| 모종 사정 | `test-seedlings.md` |
| 대상 · 장비 · 성공 기준 | `problem-definition.md` 먼저 |

## 6. 안전 · 하지 말 것

- ⚠️ **그리퍼를 움직이는 명령**(초기화 · 위치 · 닫기)은 실행 직전에 "손끝 사이에 손이나 물건 없음"을 사용자에게 확인받는다 — 손끝이 칼날이다
- AG-95 **주소 · 통신 속도 변경, 설정 저장(0x0300) 금지**
- 전원 장치 출력은 멀티미터로 잰 뒤에만 연결한다 (checklist P1-1)
- `sudo` 명령은 보여주기만 하고, 사용자가 터미널에서 직접 실행한다
- 오래 도는 명령은 사용자가 VS Code 터미널에서 실행하고, 출력은 `@terminal:이름`으로 받는다
- 재배 기준 문서 원본(이미지)은 저장소에 넣지 않는다 — 공개 여부 미확인
- `push`는 사용자 확인 후
