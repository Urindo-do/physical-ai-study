# Day 2 — Ubuntu 22.04 재설치 & 리눅스 개념 심화

**날짜**: 2026-08-19
**작업 환경**: 랩 지급 노트북 (Lenovo Legion 5, hostname `urindodo-Lenovo-Legion-5-15IMH05H`)

---

## 1. 결정 번복: 20.04 유지 → 22.04 재설치

전날 지도 교원이 "20.04 유지"를 권했으나, 이후 팀 논의를 거쳐 **22.04로 재설치하기로 최종 결정**됨. 이유: ROS 2 Humble의 공식 지원 버전이 22.04이고, 20.04용 배포판(Foxy)은 2023년 5월 EOL이라 장기적으로 22.04 전환이 불가피하다고 판단.

---

## 2. 재설치 전 안전 절차

1. **미사용 파티션 내용 확인**: `sudo file -s /dev/nvme0n1p2` → NTFS로 확인됨 (예전 윈도우 흔적으로 추정). 랩 공용 노트북이고 아무도 중요하다고 언급하지 않아 삭제 진행하기로 판단.
2. **설치 USB 검증**: 윈도우에서 USB 포맷 요청 창이 떴으나 **포맷하지 않음** (정상 동작 — 부팅 USB는 윈도우가 못 읽는 구조라 뜨는 안내). `diskpart` → `list volume`으로 크기 확인(4799MB + 300KB = ISO+EFI 구조, Ubuntu 22.04 데스크톱 이미지 크기와 일치), 리눅스에 마운트해서 `.disk` 폴더 및 볼륨 라벨로 `Ubuntu 22.04.3 LTS amd64` 최종 확인.

## 3. 설치 진행

- 부팅 메뉴(F12)에서 **USB HDD** 선택 (참고: "ubuntu (SAMSUNG...)" 항목은 기존 내장 디스크의 20.04를 그대로 부팅하는 것이라 헷갈리기 쉬움 — USB 설치 항목과 구분 필요)
- GRUB 메뉴에서 **Try or Install Ubuntu** 선택
- 언어: English (US) 통일 (시스템 언어/키보드 레이아웃 모두)
- Wi-Fi 연결 후 Updates and other software: **Normal installation** + **Download updates** + **Install third-party software(그래픽/Wi-Fi 드라이버)** 모두 체크
- **Installation type: "Erase disk and install Ubuntu"** 선택 (기존 20.04 파티션만 지우는 옵션과 구분 — 전자는 디스크 전체를 밀어 새 22.04가 954GB 전부를 쓸 수 있게 함)
- 타임존: Seoul로 자동 인식됨 (광주와 시간대 동일하여 문제없음, 대한민국은 단일 시간대)
- 계정: 사용자명 `Urindodo`(호스트명엔 `urindodo`로 반영), **"Require my password to log in"** 선택 (Active Directory는 사용 안 함)
- 재부팅 시 업그레이드 팝업 주의: **24.04 업그레이드 제안은 거절**, 22.04 내 일반 보안 업데이트(Install Now)는 수락

### 설치 후 검증 결과

→ 예전 NTFS 파티션들 모두 제거, 깨끗한 단일 OS 구조로 재구성됨

### 미해결/관찰 사항
- 화면 하단에 지속적인 그래픽 줄무늬 발생 — 설치 전/중/후 모두 동일 위치에서 발생하여 **드라이버가 아닌 디스플레이 패널/케이블 쪽 하드웨어 이슈일 가능성**으로 판단, 랩 담당자 확인 필요 (사용에는 지장 없음)

## 4. 한글 입력 재설정 (성공)

전날 20.04에서 실패했던 것과 동일한 절차를 재설치 후 다시 시도:
```bash
sudo apt install language-pack-ko ibus-hangul -y
sudo reboot
im-config -n ibus
sudo reboot   # 이 재부팅이 핵심 — im-config 변경은 로그인 세션이 새로 시작돼야 전체 프로그램에 적용됨
```
- **결과: 성공.** 예전 실패 원인은 예전 사용자(추정 중국어권)의 로케일 설정 충돌로 추정, 재설치로 깨끗하게 해결됨
- 남은 이슈: `Super+Space` 단축키가 씹혀서 화면 오른쪽 위 클릭으로만 전환 가능 → `Switch to next input source` 단축키 재설정 필요 (Input Sources 목록에 English 항목이 중복돼 있는 것으로 추정, 확인 중)
- ⚠️ 주의: `language-pack-ko` 설치 후 Region & Language의 **Language 필드가 자동으로 "한국어"로 바뀌는 부작용 발견** → English (United States)로 즉시 되돌림. 과제 요구사항(시스템 언어 English 유지)과 충돌하니 재설치/업데이트 후에는 항상 이 필드 재확인 필요

## 5. 개념 학습 — 심화

### 5-1. 파티션 TYPE 3종 구분
| TYPE | 의미 |
|---|---|
| disk | 물리 저장장치 자체 |
| part | 물리 디스크를 나눈 구역 |
| loop | 파일 하나를 디스크처럼 위장시킨 가상 장치 (snap이 사용) |

### 5-2. 재설치해도 파티션이 1개가 아니라 3개인 이유
"전체 디스크 삭제 후 설치"를 해도 부팅 구조상 최소 3개 필요:
- BIOS Boot Partition (1M, 부트로더 코드)
- EFI System Partition (513M, `/boot/efi`, UEFI 부팅 정보)
- 루트 파티션 (나머지 전체, `/`)

### 5-3. snap이 존재하는 이유
전통적 apt 방식은 프로그램들이 라이브러리를 서로 공유하다 버전 충돌("dependency hell")이 발생. snap은 프로그램마다 필요한 부품을 통째로 봉인해서 배포 → 충돌 없음, 대신 용량 더 사용. **아나콘다 가상환경과 유사해 보이지만 다름**: conda는 "환경을 전환"하는 방식(activate), snap은 "프로그램이 자기 부품을 항상 지니고 다니는" 방식.

### 5-4. loop 장치가 필요한 이유
snap 파일은 사실상 작은 디스크 이미지. 리눅스 커널은 파일시스템을 "마운트"로만 다룰 수 있는데, 마운트는 원래 물리 디스크 전용 기능. loop 장치는 "이 파일을 디스크인 척 위장"시켜 커널이 기존 마운트 메커니즘을 그대로 재사용할 수 있게 해주는 다리 역할. (더 많은 저장공간이 필요해서가 아니라, 봉인된 패키지의 내용을 읽기 위한 방편)

### 5-5. mount 개념과 윈도우와의 근본적 차이
mount = 저장장치(또는 loop처럼 위장된 것)의 내용을 폴더 트리 안의 특정 위치에 연결하는 행위.
- **윈도우**: 저장장치마다 새 드라이브 문자(`D:`, `E:`) 배정 — 장치별로 새 출입구 생성
- **리눅스**: `/` 하나짜리 폴더 트리만 존재. 새 저장장치는 기존 트리의 빈 폴더에 "이식"됨 (예: USB → `/media/사용자이름/이름`)
- 실전 이점: 경로가 고정되므로 자동화 스크립트 작성이 안정적 (로봇이 SD카드를 항상 같은 경로에서 인식하게 만들 수 있음). ROS 2를 포함한 로봇공학/서버 분야가 리눅스를 표준으로 삼는 이유 중 하나.

### 5-6. FHS (Filesystem Hierarchy Standard) — 표준 폴더명의 어원
모든 리눅스 배포판이 공통으로 따르는 폴더 구조 규칙. 원래 영단어를 알면 암기가 쉬움:

| 폴더 | 원어 | 뜻 |
|---|---|---|
| `bin` | binary | 실행 프로그램 |
| `sbin` | system binary | 관리자 전용 실행 프로그램 |
| `lib` | library | 공유 라이브러리 (matplotlib의 lib과 동일 어원) |
| `etc` | et cetera | 설정 파일 (최근엔 "Editable Text Configuration"으로 재해석되기도 함) |
| `usr` | 원래 user, 지금은 공용 프로그램 자료 | 역할이 시간에 따라 변한 대표 사례 |
| `dev` | device | 하드웨어 장치 파일 |
| `var` | variable | 계속 바뀌는 데이터 (로그 등) |
| `tmp` | temporary | 임시 파일 |
| `boot` | bootstrap | 부팅 관련 파일 |
| `opt` | optional | 선택 설치 소프트웨어 |
| `proc` | process | 실행 중인 프로세스 정보 (가상 파일시스템) |

윈도우는 "프로그램별 정리"(Program Files\프로그램이름), 리눅스는 "역할별 정리"(bin/etc/lib에 흩어짐) — snap이 나온 이유 중 하나가 이 흩어짐 문제 해결.

## 6. Claude Desktop 앱 설치 (리눅스, 베타)

공식 지원: Ubuntu/Debian (x64, arm64). 설치 절차:
```bash
sudo apt install curl -y
sudo curl -fsSLo /usr/share/keyrings/claude-desktop-archive-keyring.asc https://downloads.claude.ai/claude-desktop/key.asc
echo "deb [arch=amd64,arm64 signed-by=/usr/share/keyrings/claude-desktop-archive-keyring.asc] https://downloads.claude.ai/claude-desktop/apt/stable stable main" | sudo tee /etc/apt/sources.list.d/claude-desktop.list
sudo apt update && sudo apt install -y claude-desktop
```
- 설치 성공 확인: `which claude-desktop` → `/usr/bin/claude-desktop`
- 설치 중 `qemu-system`, `qemu-kvm` 등 가상화 패키지가 의존성으로 함께 설치됨 (코드 실행/파일 작업을 격리된 샌드박스에서 처리하기 위함으로 추정)
- Computer Use 기능은 리눅스 베타에서 아직 미지원
