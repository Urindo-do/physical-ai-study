# 리눅스 기초 명령어 실습 — 미니 시나리오

날짜: 2026-08-18
목표: `physical-ai-study`라는 실습용 폴더를 직접 만들고 다뤄보면서, 과제 안내서 ④번(경로 이동/탐색, 파일·디렉터리 제어, 권한·패키지 관리)에 나온 명령어를 손으로 익힌다.

체크포인트마다 "내가 예상한 결과"와 "실제 결과"를 비교해보고, 다르면 왜 다른지 생각해보고 넘어갈 것.

---

## 0단계. 지금 내가 어디 있는지 확인

```bash
pwd
```
- **뜻**: print working directory, 지금 터미널이 위치한 폴더 경로를 보여줌.
- **예상 결과**: 보통 `/home/사용자이름` (홈 디렉터리)가 나옴.
- **체크포인트**: 내 사용자 이름이 경로에 그대로 보이는지 확인.

---

## 1단계. 실습 폴더 만들기

```bash
mkdir linux-practice
cd linux-practice
pwd
```
- `mkdir` (make directory): 폴더 생성.
- `cd` (change directory): 그 폴더 안으로 이동.
- 마지막 `pwd`로 정말 그 폴더 안으로 들어갔는지 재확인 — 새 명령어를 쓴 뒤엔 `pwd`나 `ls`로 결과를 확인하는 습관을 들이면 좋음.

**체크포인트**: `pwd` 결과 끝이 `/linux-practice`로 끝나는지 확인.

---

## 2단계. 폴더 안이 비어있는지 확인

```bash
ls
ls -a
```
- `ls` (list): 지금 폴더 안 파일/폴더 목록.
- `-a` 옵션(all): 숨김 파일까지 다 보여줌. 리눅스는 이름이 `.`으로 시작하면 숨김 파일이 됨.
- **예상 결과**: `ls`는 아무것도 안 나옴(빈 폴더라서). `ls -a`는 `.`과 `..`만 나옴 — `.`은 "지금 폴더 자기 자신", `..`은 "한 단계 위 폴더"를 가리키는 특수 표시임 (윈도우엔 없는 개념).

---

## 3단계. 빈 파일 여러 개 만들기

```bash
touch notes.txt
touch todo.txt backup.txt
ls -l
```
- `touch`: 원래는 파일의 "수정 시각"만 갱신하는 명령어지만, 대상 파일이 없으면 빈 파일을 새로 만들어줌. 그래서 실무에서는 "빈 파일 생성"용으로 제일 많이 씀.
- 한 줄에 파일 이름을 여러 개 나열하면 한 번에 여러 개 생성 가능.
- `-l` 옵션(long): 파일마다 권한, 소유자, 용량, 수정 날짜까지 자세히 보여줌.

**체크포인트**: `ls -l` 결과에서 맨 앞 `-rw-rw-r--` 같은 문자열이 보일 텐데, 이게 "권한" 표시야 (6단계에서 다시 다룸).

---

## 4단계. 파일에 내용 써보기

```bash
nano notes.txt
```
- `nano`: 터미널 안에서 쓰는 텍스트 편집기 (윈도우 메모장 같은 역할).
- 아무 문장이나 한 줄 써보기 (예: `오늘은 리눅스 기초 명령어를 연습했다`).
- 저장하고 나가기: `Ctrl + O` (저장, Write Out) → `Enter` → `Ctrl + X` (종료, eXit).

```bash
cat notes.txt
```
- `cat`: 파일 내용을 화면에 그대로 출력. 방금 쓴 문장이 그대로 보이면 성공.

**체크포인트**: `cat notes.txt` 결과가 내가 nano에서 쓴 문장과 똑같은지 확인.

---

## 5단계. 복사 / 이동 / 이름변경

```bash
cp notes.txt notes_backup.txt
ls
```
- `cp` (copy): `원본 → 복사본` 순서로 씀. `notes_backup.txt`라는 복사본이 새로 생김 (원본은 그대로 남음).

```bash
mv todo.txt archive/todo.txt
```
- 어? 이건 실패할 거야 — `archive`라는 폴더가 아직 없어서. 일부러 넣어본 실패 케이스임.
- **체크포인트**: 에러 메시지가 뭐라고 나오는지 읽어보기. 리눅스는 에러 메시지에 원인이 꽤 친절하게 적혀 있는 편이라, 앞으로도 에러 나면 당황하지 말고 메시지부터 읽는 습관이 중요함.

```bash
mkdir archive
mv todo.txt archive/todo.txt
ls
ls archive
```
- 이번엔 폴더를 먼저 만들었으니 성공할 거야.
- `mv` (move): 파일을 다른 위치로 옮김. 같은 폴더 안에서 이름만 다르게 쓰면 "이름 변경"으로도 쓰임 (예: `mv backup.txt old_backup.txt`).

**체크포인트**: `ls`에는 이제 `todo.txt`가 안 보이고, `ls archive`에는 보이는지 확인.

---

## 6단계. 권한 실습 (sudo, chmod)

```bash
ls -l notes.txt
```
- 맨 앞 `-rw-rw-r--` 읽는 법: 총 10글자 중 앞 1글자는 종류(`-`=파일, `d`=폴더), 그다음 3글자씩 세 묶음이 각각 **소유자(owner) / 그룹(group) / 그 외 모두(others)** 권한을 뜻함. `r`=읽기, `w`=쓰기, `x`=실행, `-`=권한 없음.

```bash
chmod a-w notes.txt
echo "테스트" >> notes.txt
```
- `chmod` (change mode): 권한을 바꾸는 명령어. `a-w`는 "all(모두)에서 write(쓰기) 권한을 뺀다"는 뜻.
- 그 상태에서 `echo ... >> notes.txt`(파일에 내용 추가하려는 시도)를 하면 **Permission denied(권한 거부)** 에러가 뜰 거야 — 방금 내가 쓰기 권한을 스스로 없앴기 때문.

```bash
chmod a+w notes.txt
echo "테스트" >> notes.txt
cat notes.txt
```
- `a+w`로 다시 쓰기 권한을 돌려주면 정상적으로 추가됨.

**체크포인트**: 권한을 뺐을 때와 되돌렸을 때 결과가 다르게 나오는 걸 직접 눈으로 확인.

---

## 7단계. 패키지 관리 (sudo apt)

```bash
sudo apt update
```
- `apt`: 우분투의 패키지(프로그램) 관리자. `update`는 "설치 가능한 패키지 목록을 최신으로 갱신"하는 것 — 아직 아무것도 설치 안 함, 목록만 새로고침.
- `sudo`가 필요한 이유: 시스템 전체에 영향을 주는 작업이라 관리자 권한 필요.

```bash
sudo apt install tree
```
- `tree`라는 가벼운 프로그램을 설치. 폴더 구조를 트리 모양(`lsblk`에서 봤던 것과 비슷한 형태)으로 보여주는 도구라, 오늘 만든 `linux-practice` 폴더 구조를 눈으로 확인하기 좋음.

```bash
tree
```
- 지금까지 만든 `notes.txt`, `notes_backup.txt`, `archive/todo.txt` 등이 트리 구조로 한눈에 보일 거야.

**체크포인트**: 지금까지 1~6단계에서 만든 파일/폴더가 `tree` 결과에 다 들어있는지 확인 — 하나라도 안 보이면 그 단계를 다시 점검.

## 마무리 정리 (선택)

다 해봤으면 실습 폴더를 통째로 지워서 깔끔하게 정리해도 됨:

```bash
cd ..
rm -r linux-practice
```
- `-r` 옵션(recursive): 폴더 안에 파일이 들어있어도 통째로 삭제. `-r` 없이 `rm`만 쓰면 폴더는 못 지움(에러 남).
- ⚠️ `rm -r`은 휴지통을 거치지 않고 즉시 영구 삭제라서, 실무에서 진짜 조심해야 하는 명령어야. 지울 폴더 이름을 두 번 확인하는 습관을 들이자.
