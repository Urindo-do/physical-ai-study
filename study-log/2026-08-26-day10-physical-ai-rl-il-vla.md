## 0. ROS 2 이월 작업 완료

Day 5(8/21)부터 미뤄져 있던 `ros_domain` alias 등록을 오늘 끝냈다.

```bash
alias ros_domain="export ROS_DOMAIN_ID=13; echo \"ROS_DOMAIN_ID=13\""
alias humble="source /opt/ros/humble/setup.bash; ros_domain; echo \"ROS2 humble is activated\""
```

검증: 새 터미널 → `humble` → `ROS_DOMAIN_ID=13` / `ROS2 humble is activated` 두 줄 출력 → `echo $ROS_DOMAIN_ID`가 `13` 반환. ✅

### 겪은 문제 3가지

**① alias 안의 alias는 정의 순서와 무관하다**
`humble`이 `ros_domain`보다 파일에서 위에 있어도 정상 동작한다. bash는 alias를 **정의할 때가 아니라 명령을 입력받는 순간에** 펼치기 때문이다. (직접 순서를 뒤집어 테스트해서 확인)

**② `export`가 필요한 이유**
`ros2`는 터미널이 새로 띄우는 **별개의 프로그램(자식 프로세스)** 이다. `export` 없이 `ROS_DOMAIN_ID=13`만 하면 그 값이 터미널 안에만 갇혀서 `ros2`가 못 본다.

| | 만드는 법 | 누가 보나 |
|---|---|---|
| 셸 변수 | `MYVAR=13` | 이 터미널만 |
| **환경변수** | `export MYVAR=13` | 이 터미널 + 여기서 실행하는 모든 프로그램 |

**③ `.bashrc`가 문법 에러로 깨지면 그 터미널은 회복 불가**
따옴표 짝이 안 맞아 `unexpected EOF while looking for matching` 에러가 났다. 이때 그 터미널은 `.bashrc`를 **읽다가 중간에 멈춘** 상태라 `rebash`(=`source ~/.bashrc`) alias 자체가 등록되지 않는다. 없는 명령을 부르니 `command not found`가 뜬 것.
→ **`.bashrc`가 한 번 깨졌으면 `rebash`가 아니라 터미널을 새로 열어야 한다.**
→ 고치기 전에 `bash -n ~/.bashrc`로 문법만 먼저 검사하면 안전하다. (`-n` = no execute)

## 1. 피지컬 AI가 왜 중요한가

강사님 표현이 핵심을 잘 짚는다.

> LLM이 **지식 노동의 인터페이스**를 바꿨다면, 피지컬 AI는 **물리적 작업의 인터페이스**를 바꿀 것이다.

- 적용 분야: 공장, 물류
- 핵심 요구사항: **AI가 현재 상황을 보고 스스로 명령을 바꿀 수 있어야 한다**
  (미리 짜둔 시나리오대로만 움직이는 기존 산업용 로봇과의 결정적 차이)
- 여러 분야가 전부 이어져야 하는 영역이라, 오래 붙잡고 공부할 대상이다.

**오늘 다룬 세 축**

| 축 | 한 줄 요약 |
|---|---|
| 강화학습 (RL) | 해보고 보상받으며 스스로 배운다 |
| 모방학습 (IL) | 전문가가 한 걸 보고 따라 한다 |
| VLA | 보고(Vision) 듣고(Language) 움직인다(Action) |

**VLA(Vision-Language-Action)**: 로봇이 이미지를 보고, 언어 명령을 이해하고, 실제 동작을 실행하는 것.

## 2. 강화학습 (Reinforcement Learning)

### 기본 구조

에이전트가 **환경과 상호작용하면서** 좋은 방법을 배우는 방식. 정답이 주어지지 않고, 직접 해보고 받은 **보상**으로 배운다.

```
상태 s → [정책 π] → 행동 a → 환경 → 보상 r + 다음 상태 s'
   ↑                                        │
   └────────────────────────────────────────┘
```

이 단계들이 쌓이면 **episode**를 이루고, episode 하나가 학습 단위가 된다.

### 구성 요소 (로봇팔 예시)

| 요소 | 기호 | 로봇팔에서의 예 |
|---|---|---|
| 상태 | s | 카메라 이미지, 관절 각도, 그리퍼 상태 |
| 정책 | π(a\|s) | 상태를 보고 행동을 고르는 규칙 (**학습 가능한 모델**) |
| 행동 | a | 팔 이동, 그리퍼 닫기, 속도 조절 |
| 보상 | r | 컵 잡음 (+), 목표에 가까워짐 (+), 컵 떨어뜨림 (−) |

> ⚠️ **정정**: 필기에 `정책 파이(a\s)`로 되어 있는데, 올바른 표기는 **`π(a|s)`** 다.
> 세로 막대 `|`는 조건부 확률 기호로, "상태 s가 주어졌을 때 행동 a를 고를 확률"이라는 뜻이다.

### 정책의 두 종류

- **결정적 정책(deterministic)**: 컵이 오른쪽이면 → 무조건 오른쪽으로 이동
- **확률적 정책(stochastic)**: 상태가 주어지면 여러 행동에 각각 확률을 부여

강화학습에서는 주로 **확률적 정책**을 쓴다. 다양한 행동을 시도해보는 **탐색**이 필요하기 때문이다.

> 💡 **피지컬 AI 관점에서 정책 = 행동 생성기(action generator)**.
> 이 개념이 오늘 배운 모든 모델(ACT, Diffusion Policy, VLA, π0, GR00T)을 관통한다.
> 전부 "정책을 어떻게 더 잘 만들 것인가"에 대한 서로 다른 답이다.

### 지도학습과의 차이

| | 지도학습 | 강화학습 |
|---|---|---|
| 흐름 | 입력 x → 모델 → **정답 y와 비교** | 행동 a 실행 → **보상 r + 다음 상태 s'** |
| 정답 | 이미 주어짐 | 주어지지 않음 |
| 배우는 것 | 정답과 얼마나 비슷한가 | 상태·행동·보상의 상호작용 |

### 지연 보상 (delayed reward)

필기에 "좋은 행동을 하면 좋은 보상으로 이루어지지 않는다"고 적혀 있는데, 정확히는 **좋은 행동이 항상 즉시 보상으로 돌아오지는 않는다**는 뜻이다. 각 순간의 선택이 **쌓여서** 장기 보상을 만든다. 이걸 **credit assignment 문제**라고 부른다 — 최종 성공/실패의 공을 앞선 어느 행동에 돌릴지 정하는 문제.

### 탐색(Exploration)과 활용(Exploitation)

> 정책은 항상 좋아 보이는 행동만 골라야 할까, 새로운 시도를 해봐야 할까?

- **활용**: 지금까지 좋았던 행동을 고른다 → 안정적
- **탐색**: 새 행동을 시도한다 → 더 좋은 방법을 발견할 수도 있지만, **안전 문제**가 생길 수 있음

둘 사이의 **균형**을 맞추는 것이 강화학습의 핵심 과제 중 하나다.

### 실제 로봇에 적용할 때의 3가지 벽

| 문제 | 내용 | 왜 로봇에서 특히 심각한가 |
|---|---|---|
| **샘플 비효율성** | 많은 시행착오가 필요 | 실제 로봇은 시간·비용이 크다 |
| **희소한 보상** | 중간 행동은 평가하기 어려움 | 성공/실패만 알려주면 중간을 배울 수 없다 |
| **안전 문제** | 무작위 탐색은 위험 | 로봇·환경·사람에게 손상이나 부상 |

**→ 이 세 가지 때문에 모방학습이 등장한다.**

## 3. 모방학습 (Imitation Learning)

### Behavior Cloning (BC)

전문가가 한 행동을 보고 그대로 따라 하는 것.

1. **전문가 시연** — 사람이 좋은 행동을 직접 보여줌
2. **시연 데이터셋** — 상태-행동 쌍 `(s, a)`을 모음
3. **정책 학습** — 상태를 보면 전문가처럼 행동하도록 학습

```
일반 지도학습 :  입력  →  모델  →  정답 라벨
Behavior Cloning: 상태 s →  정책 π →  전문가 행동 a
```

> 💭 **내 메모**: 아 이래서 지도학습이 로봇팔에서 봤던 거로 느껴졌던 거구나.
> → 맞는 직관이다. **BC는 구조적으로 지도학습이다.** 다만 라벨이 "정답 클래스"가 아니라 "전문가의 행동"일 뿐이다.

**그런데 결정적인 차이가 있다.**

| | 지도학습(이미지 분류) | Behavior Cloning |
|---|---|---|
| 출력 | 라벨 | **물리 세계에서 실행되는 행동** |
| 시간 | 한 번 예측하면 끝 | **연속적인 제어**, 시간이 이어짐 |
| 실수의 대가 | 오분류 1건 | 로봇·사람이 다칠 수 있음 |
| 다음 입력 | 내가 뭘 예측했든 무관 | **내 행동이 다음 입력을 바꾼다** ← 핵심 |

마지막 줄이 모든 문제의 근원이다.

### 한계 ① Distribution Shift와 누적 오차 (Compounding Error)

**훈련할 때의 상태 분포**와 **실제 실행 중 마주치는 상태 분포**가 다르다.

```
작은 실수 → 경로에서 조금 벗어남 → 훈련데이터에 드문 상태
         → 더 큰 실수 → 실패 (compounding error = 누적 오차)
```

모델은 완벽하지 않아 오차가 난다. 이미지 분류라면 한 장 틀리고 끝이지만, 로봇은 **매 순간 출력이 다음 상태를 바꾸기 때문에** 작은 오차가 훈련 분포 밖 상태로 데려간다. 그리고 그런 상태는 배운 적이 없어서 **회복하지 못한다.**

> 📐 **[확인] 이론적 근거** — Ross & Bagnell, *Efficient Reductions for Imitation Learning* (CMU, AISTATS 2010)
> 전문가 상태 분포에서 잰 오차가 ε일 때, T-step 누적 비용은 최악의 경우
> **`J(π̂) ≤ J(π*) + T²ε`**
> 일반 지도학습이 T에 **선형(O(T))** 인 반면 BC는 **2차(O(T²))** 로 커진다.
> 논문은 이 bound가 **tight**(더 못 줄임)임도 함께 보였다. 즉 "운 나쁘면"이 아니라 구조적 한계다.
>
> 반대로, 전문가의 "실수 1회당 손해"가 `u`로 제한되면 `J(π̂) ≤ J(π*) + uTε`로 **선형까지 완화**된다.
> → **한 번 삐끗해도 복구 가능한 태스크일수록 BC가 잘 먹힌다**는 뜻이기도 하다.

**로봇 제어에서는 한 순간의 정답보다 전반적인 흐름이 중요하다.** 이 문장이 오늘 강의의 핵심 통찰이다.

### 한계 극복 시도 3가지

**1. 다양한 시연 데이터** — 여러 시작 상태·물체 위치에서 성공 시연을 모아 상태 다양성을 늘린다.

**2. 복구 행동 포함** — 경로에서 벗어났다가 다시 목표로 돌아오는 데이터를 일부러 넣는다.
   (성공한 데이터만 모으면 "실패에서 빠져나오는 법"을 영영 못 배운다)

**3. DAgger**

> ⚠️ **정정**: 필기의 `Dataset Agrigation` → 올바른 철자는 **`Dataset Aggregation`**.
> [확인] Ross, Gordon, Bagnell (CMU), AISTATS 2011, arXiv 1011.0686. 논문 §3 원문에 "DAGGER (Dataset Aggregation)"으로 명시.

핵심은 **데이터셋을 교체하는 게 아니라 계속 누적(aggregate)한다**는 것. 그래서 이름이 Aggregation이다.

```
D ← ∅
for i = 1..N:
    πᵢ = βᵢ·π*(전문가) + (1−βᵢ)·π̂ᵢ(학습정책)     # 섞어서 실행
    πᵢ로 궤적을 굴려 방문한 상태들을 모음
    Dᵢ = {(s, π*(s))}                            # 그 상태에 전문가가 재라벨링
    D ← D ∪ Dᵢ                                   # ★ 누적
    π̂ᵢ₊₁ ← D 전체로 재학습
```

- `β₁ = 1`로 시작 → 첫 회는 순수 전문가 데이터부터 출발
- **[확인] 효과**: T에 대해 **선형** 보장 (`J(π̂) ≤ J(π*) + uT·ε_N + O(1)`). BC의 O(T²)를 O(T)로 낮춘 것이 이 논문의 기여다.

**핵심 아이디어 한 줄**: 훈련 분포와 실행 분포가 달라서 생기는 문제니까, **실행 중 실제로 만나는 상태를 훈련 데이터에 집어넣자.**

> ⚠️ **[확인] DAgger의 실용적 단점**: 매 iteration마다 **전문가가 계속 붙어 있어야 한다.**
> 학습 정책이 방문한 모든 상태에 전문가가 라벨을 달아줘야 하므로 사람 비용이 크다.
> (원논문은 이 부담을 명시적으로 논하지 않았고, 후속 논문 **HG-DAgger**(Stanford/UIUC, 2019)가
> ① 제어권 없는 상태에 사후 라벨링해야 함 ② 제어권 전환이 전문가 조작 자체를 왜곡 ③ 미숙한 정책이
> 굴러가는 동안의 안전 문제 — 세 가지로 정리했다.)

## 4. 행동은 한 순간이 아니라 시퀀스다 — ACT

### 문제 제기

행동은 이어진다. 상태도 그에 맞춰 계속 바뀐다. 이 이어진 전체 흐름을 **Trajectory(궤적)** 라고 한다.

> 💭 **내 메모**: 이 대목에서 RNN·어텐션이 떠올랐다.
> → 좋은 연결이다. 실제로 ACT는 **Transformer**를 쓴다.

**한 step씩 예측하면 행동이 흔들린다.** 각 스텝의 계산이 서로 독립적이라, 겉보기엔 자연스러워 보여도 실제 로봇 제어에서는 출력 하나하나가 따로 놀아 전체 움직임이 부자연스러워진다.

### ACT: Action Chunking with Transformers

> 📄 **[확인]** 논문 정식 제목은 **"Learning Fine-Grained Bimanual Manipulation with Low-Cost Hardware"**
> (제목에 ACT나 ALOHA가 안 들어간다 — 검색할 때 주의)
> Tony Z. Zhao, Vikash Kumar, Sergey Levine, Chelsea Finn (Stanford / UC Berkeley / Meta), **RSS 2023**, arXiv 2304.13705

**핵심 아이디어**: 행동을 하나씩 뱉지 말고, **앞으로의 행동 묶음(action chunk)을 통째로** 예측하자.

```
Behavior Cloning : 상태 → 행동 1개
ACT              : 상태 → 행동 k개 묶음 (action chunk)
```

**[확인] 구체 수치**
- **chunk 크기 k = 100**, 제어 주파수 **50 Hz** → 한 번에 **약 2초 분량**의 행동을 예측
- 태스크당 시연 **50개** (약 10~20분 분량)로 성공률 **80~90%** 달성

**[확인] 구조 — CVAE다**
| 부분 | 내용 |
|---|---|
| Encoder (학습 때만) | Transformer encoder, `[CLS]` 토큰. 현재 관절 위치 + 목표 행동 시퀀스 → 스타일 변수 **z** |
| Decoder (= 정책) | **ResNet-18** 이미지 백본 + Transformer encoder-decoder. z + 관측 → 길이 k 행동 시퀀스 |
| 추론 시 | **z = 0** (prior 평균)으로 고정하고 encoder는 버린다 |
| 손실 | `L1` 재구성 + `β·KL`, **β = 10** (L2가 아니라 **L1**인 점 주의) |

**[확인] Temporal Ensembling**
매 timestep마다 chunk를 새로 만들면 같은 시각 t에 대한 예측이 여러 개 겹친다. 이걸 지수가중 평균한다.
`wᵢ = exp(−m·i)` — m이 작을수록 새 예측을 빨리 반영.
> ※ m 값은 **논문 본문에 미기재**. 공식 구현 코드(`imitate_episodes.py`)에는 `k = 0.01`로 되어 있다.
> (논문 미명시 / 코드 0.01 — 구분해서 기억)

**이 방식이 왜 로봇 제어에 현실적인가**: 전체 태스크를 통째로 예측하는 게 아니라 **가까운 미래(약 2초)만** 예측하고 계속 갱신하기 때문이다. 시간적 일관성은 얻으면서 반응성도 잃지 않는다.

→ 이 모델로 만든 로봇이 **ALOHA**다.

## 5. Diffusion Policy

> 📄 **[확인]** *Diffusion Policy: Visuomotor Policy Learning via Action Diffusion*
> Cheng Chi 외, **Columbia University + Toyota Research Institute + MIT**, RSS 2023 (확장판 IJRR 2024), arXiv 2303.04137

ACT와 겉보기엔 비슷하다 — 카메라 이미지와 상태를 받아 앞으로의 행동 시퀀스를 낸다. **차이는 "어떻게" 만드느냐다.**

**행동 시퀀스를 한 번에 찍어내지 않는다.** 전문가 데이터에 노이즈를 섞어 흐트러뜨리고, 모델은 **그 노이즈를 어떻게 제거해야 원래대로 돌아가는지**를 배운다. 추론할 때는 순수 노이즈에서 시작해 여러 번 정제(denoising)해서 그럴듯한 행동 시퀀스를 만든다.

> 💭 **내 메모**: 확률분포를 만들어내는 거네
> → **정확한 이해다.** 하나의 정답 행동을 찍는 게 아니라 **가능한 행동들의 확률분포**를 생성한다.

**[확인] 왜 다봉성(multimodality)을 다룰 수 있나** — 두 군데에서 확률이 들어간다.
1. **초기 노이즈가 매번 다름** → 서로 다른 "수렴 골짜기"로 출발
2. **샘플링 과정 자체가 확률적** → 여러 mode 중 하나로 수렴

일반 회귀 정책은 여러 정답을 **평균 내버려서** 아무 데도 못 가는 행동을 만드는데, diffusion은 그걸 피한다.

**[확인] Receding Horizon Control** — 전체 시퀀스를 고정 실행하지 않고 일부만 실행하고 다시 계획한다.
| 기호 | 의미 | 기본값 |
|---|---|---|
| `T_o` | 관측 스텝 수 | 2 |
| `T_p` | 예측 horizon | **16** |
| `T_a` | 실제 실행 스텝 수 | **8** |

즉 **16 step 예측 → 8 step만 실행 → 재계획**. 논문 표현으로 "일관성과 반응성의 균형".

**[확인] 학습/추론**: DDPM으로 **100 iteration** 학습, 추론은 **DDIM**으로 가속.
> ※ 논문 본문은 추론 10 step, 하이퍼파라미터 표는 16 step으로 **불일치**가 있다.
> "학습 100 / 추론 10~16"으로 기억하는 게 안전.

**[확인] 성능**: 4개 벤치마크 12개 태스크 평균 **+46.9%** 개선.

### 장점 정리
1. 정답 하나만 만들지 않으므로 **다양한 행동 경로**를 만들 수 있다
2. 매 스텝 다시 계획하므로 **오류가 생겨도 유연하게 대처**할 수 있다

## 6. BeyondMimic — 모방을 넘어서

> 📄 **[확인]** *BeyondMimic: From Motion Tracking to Versatile Humanoid Control via Guided Diffusion*
> UC Berkeley + Stanford, arXiv 2508.08241 (2025-08). 하드웨어는 **Unitree G1** 휴머노이드.
> ※ 학회 게재 여부는 **미확인** (현재까지 arXiv 프리프린트로만 확인됨)

핵심은 **모방에서 끝나지 않는 것**이다. 사람의 고난이도 전신 동작을 로봇이 수행 가능한 기술로 바꾸고, 그것들을 **새로 조합해서** 태스크를 수행한다.

### [확인] 논문 원문의 3단계 구조

| 단계 | 내용 |
|---|---|
| **1. 통합 motion tracking** | 강화학습으로 동작을 따라 하게 학습. **동작마다 하이퍼파라미터를 따로 튜닝하지 않고 하나의 설정으로** 공중제비·스핀킥·전력질주까지 학습한 것이 핵심 기여 |
| **2. 통합 latent diffusion** | 학습된 스킬들을 **하나의 latent diffusion 모델**로 묶어 목표 지정·태스크 전환·동작 합성 가능 |
| **3. Classifier guidance** | 학습 때 본 적 없는 태스크를 **추론 시점 최적화**로 해결 — 조이스틱 조종, waypoint 이동, 장애물 회피를 zero-shot 실기 전이 |

**[확인] 세부 수치**: 관측 history 4프레임, 예측 horizon 16, Transformer decoder 6층/4헤드/512차원(약 20M 파라미터), denoising 20 step. 로봇 CPU에서 온보드 실행, 추론 **1ms 미만**.

### [확인] 데이터셋 — 역할이 다르다
- **LAFAN1** — motion tracking 학습용 (Unitree가 리타게팅한 버전, 40개 시퀀스)
- **AMASS 일부** — latent diffusion 학습용 (다양한 보행 동작 subset)

> ⚠️ 두 데이터셋의 **용도가 다르므로** 뭉뚱그리면 부정확하다.

**참고 — 두 데이터셋이 뭔지 [확인]**
| | AMASS | HumanML3D |
|---|---|---|
| 정체 | 여러 모캡 데이터셋을 **하나의 표현으로 통합**한 DB | AMASS 등의 모션에 **자연어 설명을 붙인** 데이터셋 |
| 규모 | 15개 데이터셋 통합, 300+ 피험자, 11,000+ 모션, 40시간+ | 14,616 클립 / 44,970 문장, 총 28.59시간 |
| 표현 | SMPL 바디 모델 파라미터 | 20fps, SMPL 22관절 |
| 출처 | Max Planck Institute, ICCV 2019 | Univ. of Alberta 외, CVPR 2022 |

> ⚠️ **필기와 논문이 어긋난 부분 — 모션 토큰화(VQ-VAE)**
> 필기에는 BeyondMimic 파이프라인 안에 "모션 토큰화(VQ-VAE): 연속 모션을 이산 토큰 시퀀스로 변환"이 들어가 있다.
> 그런데 **[확인] BeyondMimic 원문은 VQ-VAE를 쓰지 않는다.** 연속 latent diffusion + classifier guidance 방식이다.
>
> VQ-VAE 모션 토큰화 자체는 **실재하는 접근**이며, 휴머노이드 제어 쪽 실제 사례는 다음과 같다:
> - **MoConVQ** (arXiv 2310.10198, SIGGRAPH 2024) — VQ-VAE + model-based RL로 물리 기반 동작을 이산 토큰으로
> - **H-GAP** (arXiv 2312.02682, UCL/Meta/Georgia Tech/Berkeley) — state-action 시퀀스를 VQ-VAE로 토큰화 후 transformer prior + MPC
>
> **추정**: 강의는 "휴머노이드 전신 제어의 일반적 파이프라인"을 설명하면서 여러 접근을 하나의 흐름으로 묶어 제시한 것으로 보인다. **BeyondMimic 논문 하나의 구조로 오해하지 않도록 구분해서 기억하자.**

**공통 마무리 절차**: 시뮬레이션에서 테스트 → 보정 → 실제 로봇 적용.

## 7. VLA (Vision-Language-Action)

### 왜 필요한가

모방학습까지 왔지만, 로봇에게 실제로 일을 시키려면 **사람과 상호작용하고 언어 명령을 이해해야 한다.**

기존 모방학습은 `상태 → 행동`이라 특정 동작은 잘하지만, **사람이 내린 명령의 의미는 알 수 없었다.** 언어 명령을 받으면 명령에 따라 **다른 행동**을 만들 수 있게 된다.

### 3단계 흐름

```
1. 장면과 명령 입력  →  2. 이해  →  3. 행동 생성
```

- 언어 명령은 단순한 텍스트가 아니라 **행동 계획에 필요한 정보**를 담고 있다
- 로봇은 문장 속 언어 요소를 **장면 속 대상과 연결(grounding)** 해야 한다
- 로봇 자신의 상태도 함께 알아야 한다

**VLA 정책 = 비전 인코더 + 랭귀지 인코더 + 로봇 state 인코더**
인코더는 들어온 내용을 **모델이 이해할 수 있는 형태로 바꿔주는 과정**이다.

핵심은 이 셋을 따로 보지 않고 **하나로 통합해서 본다**는 것 — **멀티모달 정책**이다.

---

### RT 계열 (Google / Google DeepMind)

```
RT-1 → RT-2 → RT-X / Open X-Embodiment → RT-H → Gemini Robotics
```

#### [확인] RT-1 (2022-12, RSS 2023) — 로봇 행동 정책을 Transformer로

전통적 로봇 시스템은 **동작마다 별도 파이프라인**을 만들어야 했다. RT-1은 그걸 없애고 모델이 **바로 행동을 예측**하는 end-to-end 정책을 만들었다.

| 항목 | 값 |
|---|---|
| 데이터 | **13대 로봇으로 17개월간, 약 130,000 에피소드, 700+ 태스크** |
| 비전 | EfficientNet-B3 (ImageNet 사전학습) |
| 언어 조건화 | **FiLM** 레이어 |
| 토큰 압축 | **TokenLearner** — 시각 토큰 81개 → 8개 |
| 백본 | decoder-only Transformer 8층 (19M) / 전체 **35M** |
| 행동 이산화 | 차원당 **256 구간(bins)** |
| 제어 주파수 | **3 Hz** |
| 성능 | 학습한 태스크 97% / 처음 보는 태스크 76% |

> Transformer는 원래 **시퀀스 처리 구조**라서 로봇 행동에 바로 적용된다.
> "지금 뭘 보고 있고 / 어떤 명령을 받았고 / 직전에 뭘 했나"를 보고 **다음 행동 토큰을 예측**한다.

#### [확인] RT-2 (2023-07, CoRL 2023) — 웹 지식을 행동으로 연결

RT-1의 한계: **로봇 시연 데이터를 만드는 게 어렵고 비싸다.** 그리고 로봇 데이터만으로는 세상에 대한 정보가 턱없이 부족하다.

→ **웹 규모의 시각-언어 지식**을 끌어다 쓰자.

- **핵심 기법: co-fine-tuning** — 웹 VLM 데이터(VQA 등)와 로봇 궤적 데이터를 **동시에** 파인튜닝
- 베이스 VLM: **PaLI-X (55B)**, **PaLM-E (12B)**
- **행동을 텍스트 문자열로 표현**: `"1 128 91 241 5 101 127"` 처럼 연속값을 256구간으로 나눠 정수 토큰화
- **창발 능력 3종**: ① 기호 이해 ② 추론(시각·수학·다국어) ③ 사람 인식
- 성능: 일반화가 RT-1 대비 약 **2배**, 창발 스킬은 **3배 이상**
- 추론 속도: 55B는 **1~3 Hz**

> 💭 **내 메모**: 그라운딩으로 서치하는 것과 같은 느낌이네
> → 방향이 맞다. 다만 정확히는 **검색**이 아니라 **웹 데이터로 사전학습된 지식을 행동 공간으로 전이**시키는 것이다.

#### [확인] Open X-Embodiment / RT-X (2023-10, ICRA 2024 Best Paper)

**핵심 키워드 2개: 여러 로봇 / 로봇의 몸체(embodiment)**

**Embodiment**란 로봇이 **어떤 몸을 가졌는지**를 말한다. 로봇 팔, 모바일 매니퓰레이터, 사족보행, 휴머노이드 — 겉으로는 다 로봇이지만 실제로는 전부 다르다. 과거에는 하드웨어가 다르면 정책도 따로 만들어야 했다 → **embodiment mismatch**.

| 항목 | 값 |
|---|---|
| 협업 규모 | **21개 기관**, 60개 기존 데이터셋 통합 |
| 임베디먼트 | **22종 로봇** |
| 데이터 | **100만+ 실제 로봇 궤적**, 527 스킬 / 160,266 태스크 |
| 모델 | RT-1-X (35M), RT-2-X (**55B**) |

**[확인] 핵심 발견 (positive transfer)**: RT-1-X는 소규모 데이터 도메인에서 **그 데이터셋 전용으로 학습한 방식보다 +50%** 더 잘했다. 즉 **다른 로봇의 경험이 서로에게 도움이 된다.**

> 모든 로봇에 그냥 적용된다는 뜻은 아니고 파인튜닝은 여전히 필요하다.
> 다만 **하드웨어마다 처음부터 다시 학습해야 한다면 그것 자체가 큰 장애물**이므로, 이걸 푸는 게 중요한 방향 전환이었다.

#### [확인] RT-H (2024-03) — 언어를 이용한 계층적 행동 구조

실제 현장의 태스크는 한 번의 동작으로 끝나지 않는다. "테이블을 정리해" 같은 고수준 명령에서 **바로 모터 제어로 가기는 어렵다.**

```
1층: task            "테이블을 정리해"          ← 너무 크다
2층: language motion  "팔 앞으로", "그리퍼 닫아"  ← ★ 중간 계층
3층: action          실제 모터·관절 제어값
```

> ⚠️ **중간 계층의 정확한 용어는 "language motion"** 이다. (원문 확정 용어)
> "언어 서브골", "sub-task" 등은 원문 표현이 아니다.

- 기관: **Google DeepMind Robotics + Stanford**, 백본은 RT-2와 같은 **PaLI-X 55B**
- **[확인] 어휘 구축**: 사람이 라벨링한 게 아니라 **로봇 자체 관절 정보(proprioception)에서 자동 추출**, 2,500개 이상의 language motion 라이브러리
- **[확인] 이점**
  1. **데이터 공유** — "컵 들기"와 "물병 붓기"가 *"팔 앞으로"* 라는 동작을 공유하게 된다
  2. **실행 중 사람이 언어로 즉시 교정** 가능
  3. 그 교정을 **다시 학습**해 성능 향상 (40% → 63%)
- 성능: RT-2 대비 평균 **+15%**

> 💭 **내 메모**: pick and place가 그냥 task 이름이었네
> → 맞다. 그게 1층(task)이고, 그 아래에 "팔을 뻗어라 / 그리퍼를 닫아라"가 깔린다.

#### [확인] Gemini Robotics (2025-03~) — 체화 추론(Embodied Reasoning)

**Reasoning(추론)** 은 LLM에서 주로 텍스트로 이루어지는데, **체화 추론**은 그걸 **실제 물리 세계를 이해하는 데** 쓴다. 공간을 어떻게 이해하고, 물리를 어떻게 이해하고, 작업을 어떻게 수행할지.

| 모델 | 역할 |
|---|---|
| **Gemini Robotics** | Gemini 2.0 기반 **VLA**. "물리적 행동"을 출력 모달리티로 추가 |
| **Gemini Robotics-ER** | **VLM**. 공간·시간 이해가 강화된 체화 추론 모델. 기존 저수준 컨트롤러에 연결하거나 제어 코드를 생성 |

> ⚠️ **헷갈리기 쉬운 지점**: 실행 구조에서는 **ER이 상위(계획), VLA가 하위(실행)** 인데,
> 모델 계보로는 **ER이 부모이고 VLA가 ER의 distilled 자식**이다. 방향이 반대라 구분해서 기억할 것.

**[확인] 이후 업데이트 타임라인** (2026-08 기준)

### [확인] OpenVLA (2024-06, CoRL 2024)

**기존 VLA 연구의 한계**
- 코드·가중치 접근이 어려움 → 재현과 실습이 어렵다
- 비공개 중심 생태계 → 좋은 모델을 직접 써보기 어렵다
- 새 로봇에 적용하기 어려움 → 파인튜닝 기준점이 없다

**OpenVLA는 모델 가중치와 전체 코드를 공개**해서 연구·실습·파인튜닝의 기준점이 됐다.

| 항목 | 값 |
|---|---|
| 기관 | Stanford, UC Berkeley, TRI, Google DeepMind, Physical Intelligence, MIT |
| 파라미터 | **7B** |
| 베이스 VLM | **Prismatic-7B** = (SigLIP + DINOv2 융합 비전) + Llama 2 7B |
| 학습 데이터 | Open X-Embodiment에서 **970,000 로봇 조작 궤적** |
| 행동 토큰화 | 차원당 256 구간, **Llama 토크나이저의 안 쓰는 마지막 256 토큰을 덮어씀** |
| 학습 비용 | A100 **64장 × 14일 = 21,500 A100-hours** |

**[확인] 핵심 성과**: **RT-2-X(55B)를 29개 태스크에서 절대 성공률 +16.5%p 능가.** 파라미터는 **7배 적은데** 더 잘했다.

> 다양성이 중요하다. 하나의 작업만으로 학습하면 그 동작은 잘하지만 **일반화가 안 된다.**
> 데이터에 관측·언어 명령·로봇 상태가 **함께** 들어 있다는 것이 규모보다 더 중요한 지점이다.

### 공개된 모델을 바로 내 로봇에 쓸 수 있을까? — Fine-tuning

**쉽지 않다.** 로봇은 데이터가 조금만 바뀌어도 행동의 분포가 달라진다. **일반적인 능력**과 **내 로봇에서 잘 동작하는 것**은 다르다. 하드웨어도, 카메라 위치도, 물체도 전부 다르다.

→ 내 로봇으로 직접 수행한 **소량~중간 규모의 시연 데이터**를 모아 추가 학습한다.

> 💭 **내 메모**: 진짜일까? 안 될 거 같은데?
> → **[확인] 실제로 된다.** OpenVLA 기준 **LoRA (rank r=32)** 로 전체 파라미터의 **1.4%만** 학습해도
> 전체 파인튜닝에 근접한 성능이 나온다. **A100 1장으로 10~15시간**이면 끝난다.
> 4비트 양자화는 성능 저하 거의 없이 메모리를 절반 이하(16.8GB → 7.0GB)로 줄인다.
> → 즉 **연구실 GPU 1장으로도 시도해볼 수 있는 범위**다. 이건 나중에 우리 로봇팔에 직접 해볼 만하다.

**[확인] 주의점**: 파인튜닝을 잘못하면 **기존에 잘하던 능력을 잃을 수 있다(catastrophic forgetting).**
→ **어떤 파라미터를 얼마나 적은 데이터로 학습시킬 것인가**가 핵심 문제가 된다.

## 8. π0 (파이-제로) 계열 — Physical Intelligence

> 🔎 **필기에 "설명이 굉장히 빈약하다"고 표시해둔 구간.** 논문·공식 블로그로 확인해서 보강했다.
> **중요: 필기에 π0 특징으로 적어둔 4가지 조건화는 실제로는 다른 모델(π0.7)의 내용이었다.** 아래 참고.

### [확인] π0 기본

> 📄 *π0: A Vision-Language-Action Flow Model for General Robot Control*
> Physical Intelligence (샌프란시스코), arXiv 2410.24164 (2024-10). 오픈소스 `openpi`, Apache-2.0

| 구성 | 내용 |
|---|---|
| VLM 백본 | **PaliGemma (3B)** — 인터넷 규모 의미 지식을 상속 |
| **Action Expert** | **300M** — 로봇 전용 토큰(관절 상태, 행동) 전담 |
| 총 파라미터 | **3.3B** |
| Action chunk | **H = 50** (1초 분량) |
| 제어 주파수 | **최대 50 Hz** (필기의 50Hz는 정확) |

> ⚠️ **"action expert"는 별도 모델이 아니다.** 같은 Transformer **안의 두 번째 파라미터 세트**다.
> 이미지·텍스트 토큰은 PaliGemma 가중치가, 상태·행동 토큰은 action expert 가중치가 처리하는
> **Mixture-of-Experts 방식**. VLM의 의미 지식은 보존하면서 고주파 연속 행동만 따로 전담시키는 구조다.

### [확인] Flow Matching — 필기의 "flew 기반"은 오타

정확한 이름은 **flow matching (플로우 매칭)** 이다. 작동 방식:

1. 깨끗한 행동 청크 `A`와 노이즈 `ε`를 **직선으로 보간**: `A^τ = τ·A + (1−τ)·ε`
2. 네트워크가 그 직선의 **속도 벡터 `u = ε − A`** 를 예측하도록 학습
3. 추론 시 노이즈에서 출발해 **ODE를 오일러 적분**으로 풀어 행동 생성 (π0는 **10 step**)

**diffusion과 뭐가 다른가**

| | Diffusion (DDPM/DDIM) | Flow Matching |
|---|---|---|
| 노이즈 스케줄 | 곡선형 | 선형 (`α_t = 1−t, σ_t = t`) |
| 네트워크 출력 | 노이즈 `ε̂` 또는 원본 `x̂` | **속도 `û = ε̂ − x̂`** |
| 샘플러 | DDIM | Euler ODE |

> ⚠️ **널리 퍼진 오해 하나를 짚고 간다.**
> "flow matching은 경로가 직선이라 스텝이 적게 들고 더 빠르다"는 설명은 **정확하지 않다.**
> [확인] Google DeepMind의 *Diffusion Meets Flow Matching* 분석에 따르면, 가우시안 flow matching과
> diffusion은 **수학적으로 동일한 프레임워크**이고 DDIM 샘플러와 flow matching의 Euler 샘플러는
> **같은 ODE의 동일 구현**이다. 차이는 노이즈 스케줄·출력 파라미터화·학습 가중치뿐이며,
> **flow matching이 본질적으로 샘플링 효율 우위를 갖지는 않는다.**

**그럼 π0는 왜 flow matching을 골랐나 — [확인] 논문이 밝힌 이유**

> "Flow matching provides our model with **high precision and multimodal modeling capability**,
> making it especially well suited to **high-frequency dexterous tasks**."

즉 ① 높은 정밀도 ② 다봉 분포 모델링 능력 ③ 고주파 action chunk 지원. **비교 대상은 diffusion이 아니라 RT-2 같은 오토리그레시브 이산화 VLA**다. 논문의 대조축은 `연속(flow) vs 이산(autoregressive)`이지 `flow vs diffusion`이 아니다.

> ⚠️ **미확인**: "diffusion 대신 flow matching을 택한 이유가 추론 속도"라는 서술은 **논문에 없다.**

> 💭 **내 메모**: 팔이 덜덜 떨리는 거 느꼈는데... 추론이 늘어지면 이렇게 되나?
> → 방향이 맞는 직관이다. 연속적인 세밀한 수치를 계속 만들어내야 하는데 추론이 느리면 제어가 끊긴다.
> 그래서 고주파 제어(50Hz)를 유지하는 것이 이 계열의 중요한 설계 목표다.

### ⭐ [확인] "Steerable" 4가지 조건화 — 출처 정정

필기에 **π0의 특징**으로 `언어명령 / 메타데이터 / control modality / visual subgoal` 4가지를 적어뒀는데,
**이 내용 자체는 정확하지만 π0가 아니라 π0.7의 것이다.**

> 📄 *π0.7: a Steerable Generalist Robotic Foundation Model with Emergent Capabilities*
> Physical Intelligence, arXiv 2604.15483, **2026-04-16** (2026-08 현재 최신)

π0.7 공식 블로그가 명시한 조건화 입력 — 필기의 4개와 **정확히 일치**:
1. **언어 지시** (task instruction + subtask instruction)
2. **시각적 서브골 이미지** (경량 world model이 생성)
3. **에피소드 메타데이터** (quality score, speed)
4. **control modality 라벨** (관절 제어 vs end-effector 제어)

다양한 조건을 넣는 이유는 **상황마다 다른 동작을 만들어야 하기 때문**이 맞다. 여기에 더해, 이 조건들이 있으면 **사람이 실행 중에 로봇의 행동 스타일·속도·품질을 조종(steer)** 할 수 있게 된다. 그래서 "steerable"이다.

**π0.7 사양 [확인]**: Gemma3 4B VLM + **860M action expert**, 총 약 5B. 제어 50Hz, action chunk 50, denoising **5 step**.
**주장된 창발 능력**: 파인튜닝 없이 롱호라이즌 과제(에스프레소 머신 조작, 빨래 개기, 채소 껍질 벗기기), 제로샷 cross-embodiment 전이, 저품질·실패 데이터를 섞어 학습.

> **정리**: π0(2024)의 조건화는 사실상 **언어 명령 하나**다. 4-way 조건화는 **π0.7(2026-04)** 에 붙여야 맞다.

### [확인] 계열 정리

| 모델 | 시점 | 요점 |
|---|---|---|
| **π0** | 2024-10 | PaliGemma 3B + action expert 300M, flow matching, 50Hz |
| **π0-FAST** | 2025-01 | 같은 백본·같은 데이터인데 디코딩만 **DCT 기반 FAST 토큰 + 오토리그레시브**로 교체. 학습 **최대 5배 빠름**, 대신 **추론은 더 느림**(공식 블로그가 단점으로 인정) |
| **π0.5** | 2025-04 | **처음 보는 실제 가정집**에서 주방·침실 청소. **계층적 추론** — 모델이 먼저 다음 단계를 **언어로 스스로 말하고**, 그 서브태스크에 대응하는 연속 모터 명령을 생성 |
| **π*0.6** | 2025-11 | **RECAP** — 시연 → 코칭(전문가가 실패 복구를 교정) → 자기 경험 RL. 에스프레소 제조 성공률 90%+ |
| **π0.7** | 2026-04 | steerable, 4-way 조건화 (위 참고) |

> **오픈소스 현황 [확인]**: `openpi`(Apache-2.0)에 공개된 것은 **π0, π0-FAST, π0.5**까지.
> **π0.6 / π0.7의 가중치 공개 여부는 미확인.**

## 9. GR00T — NVIDIA 휴머노이드 파운데이션 모델

> 🔎 **여기도 필기에 "되게 애매해"라고 표시해둔 구간.** 확인해서 보강했다.
> 결론부터: **필기의 "시스템2=VLM, 시스템1=diffusion+transformer"는 정확했다.** 수치를 채워 넣는다.

### [확인] 이름과 배경

- **GR00T = "Generalist Robot 00 Technology"** — 숫자 **0이 두 개**다. (`GROOT` 아님)
- **2024-03-18 GTC 2024** 젠슨 황 키노트에서 "Project GR00T"로 최초 공개

**왜 나왔나**: 지금까지의 로봇 AI는 **manipulation(물체 조작) 중심**이었다. GR00T는 방향이 다르다.
- 휴머노이드 **전신** 모델링
- **양팔 협응과 손 조작** — 전신 협응이 중요하다
- **인간 환경**에서의 작업 수행 (인간 세상은 인간 몸에 맞춰 설계돼 있으니까)
- 이해 + 행동을 함께 수행

### [확인] 듀얼 시스템 구조 — GR00T N1 (2025-03, arXiv 2503.14734)

> 💭 **내 메모**: 약간 뇌-척추 느낌이네
> → 정확히 그 비유가 맞다. 논문도 인간 인지의 이중 처리 이론에서 이름을 가져왔다.

```
장면 입력 → [System 2: 느린 사고] → [System 1: 빠른 행동] → 휴머노이드 행동 출력
```

| | **System 2 (추론)** | **System 1 (행동)** |
|---|---|---|
| 정체 | **NVIDIA Eagle-2 VLM** | **Diffusion Transformer (DiT)** |
| 파라미터 | **1.34B** | **0.86B** |
| 구성 | SmolLM2 (LLM) + SigLIP-2 (이미지) | flow matching 목적함수 |
| **동작 주파수** | **10 Hz** | **120 Hz** |
| 역할 | 상황 판단, 안전한 경로 계획 | 빠른 실시간 제어 |

**왜 나누나**: 상황 판단은 **생각하는 과정**이라 느려도 되지만, 실제 로봇 행동은 **빠르게 계속 갱신**돼야 한다. 로봇은 끊임없이 제어 명령을 받아야 하므로, 느린 추론과 빠른 제어를 **한 모델에 몰면 둘 다 망가진다.** 그래서 분리한다.

**[확인] 두 시스템의 연결 방식**: System 1의 DiT 안에서 **self-attention**은 노이즈 섞인 행동 토큰 + 상태 임베딩을 처리하고, **cross-attention**이 **System 2(VLM)가 출력한 vision-language 임베딩에 조건화**된다. 즉 System 1이 System 2의 latent를 소비한다. 두 시스템은 **엔드투엔드로 함께 학습**된다.
> 세부: VLM의 최종 레이어가 아니라 **12번째 레이어의 표현**을 쓴다. 총 2.2B 파라미터, action chunk 16개 샘플링에 L40 GPU 기준 **63.9ms**.

> ⚠️ **작은 정정**: 필기의 "diffusion"은 구조 이름 기준으로는 맞지만, **실제 학습 목적함수는 flow matching**이다.
> "Diffusion Transformer"는 **네트워크 아키텍처 이름**이고, 학습 방식은 π0와 같은 계열이다.

### [확인] 데이터 피라미드

아래로 갈수록 **양이 많고 범위가 넓으며**, 위로 갈수록 **양은 적지만 로봇에 특화**된다.

```
        ▲  실제 로봇 데이터 (텔레오퍼레이션)      ← 가장 적음, 가장 정확
       ███  합성 데이터 (Omniverse 물리 시뮬레이션)
      █████ 인터넷 웹 데이터 + 인간 에고센트릭 비디오  ← 가장 많음, 가장 넓음
```

- **시뮬레이션 궤적**: 가상 환경에서 빠르게 반복 테스트. **sim2real gap**이 있지만 그럼에도 역할이 크다
- **합성 데이터**: 실제 데이터만으로는 부족해서 보강
- **[확인] 확인된 정량 수치**: 실세계 데이터를 **약 88시간 → 827시간**으로 확장 (약 10배 증강)

> ⚠️ **미확인**: 세 층의 **구체적 비율**(예: 70:20:10)은 논문·블로그 어디에도 제시되어 있지 않다.
> "아래로 갈수록 많다"는 정성적 서술만 확인된다.

### [확인] 버전 히스토리 (2026-08 기준)

| 버전 | 시점 | 주요 변경 |
|---|---|---|
| **N1** | 2025-03 (GTC) | 2.2B, Eagle-2 VLM + DiT |
| **N1.5** | 2025-06 | VLM을 학습 내내 **frozen**, Eagle 2.5로 교체, **FLARE loss** 추가, DreamGen 합성 데이터 투입. 3B |
| **N1.6** | 2026-01 (CES) | **Cosmos Reason** 통합, **전신 제어** 지원 |
| **N1.7** | 2026-04 | 백본을 **Cosmos-Reason2-2B**로 교체, 상대 end-effector action space, 인간 비디오 **20,000시간** 사전학습. 3B |

**N1.5 성능 개선 예시**: 실제 GR-1 로봇 언어 추종 46.6% → **93.3%**, Unitree G1 학습 객체 44.0% → **98.8%**.

### [확인] Isaac GR00T / GR00T-Dreams / Cosmos 관계

```
Cosmos (world model로 데이터 생성)
  → GR00T-Dreams / DreamGen (행동 라벨 붙인 궤적으로 변환)
    → GR00T N 시리즈 (그 데이터로 학습)
```

- **Isaac GR00T**: 모델 + 시뮬레이션(Isaac Sim/Lab) + 데이터 생성 워크플로 + Jetson Thor 하드웨어를 아우르는 **플랫폼 전체 브랜드**
- **DreamGen**: 비디오 world model로 합성 로봇 비디오를 만들고, **역동역학 모델(IDM)** 로 행동을 추출해 학습 데이터로 만드는 파이프라인
- **N1.6부터는 Cosmos Reason이 모델 안으로 들어와 System 2 역할을 겸한다**

### 표기·철자

| 필기 | 정정 | 근거 |
|---|---|---|

| `val 발전` | **VLA 발전** | 오타 |

### 내용

| # | 필기 내용 | 정정 |
|---|---|---|
| 1 | **π0가 4가지로 조건화된다** (언어/메타데이터/control modality/visual subgoal) | 내용은 맞지만 **출처가 π0.7(2026-04)** 이다. π0(2024)의 조건화는 사실상 **언어 명령 하나**뿐 |
| 2 | **flow matching이 diffusion보다 빠르다**(는 뉘앙스) | **논문에 그런 근거 없음.** DeepMind 분석상 둘은 수학적으로 동치이며 본질적 샘플링 효율 우위가 없다. π0가 밝힌 실제 이유는 *정밀도 + 다봉 모델링 + 고주파 chunk 지원*이고, 비교 대상은 diffusion이 아니라 **오토리그레시브 이산화 VLA** |
| 3 | BeyondMimic 파이프라인에 **VQ-VAE 모션 토큰화**가 포함 | **BeyondMimic 원문은 VQ-VAE를 쓰지 않는다.** 연속 latent diffusion + classifier guidance 방식. VQ-VAE 모션 토큰화는 **MoConVQ / H-GAP** 등 별개 연구의 접근 |
| 4 | GR00T System 1이 **diffusion** | 구조 이름(Diffusion Transformer)은 맞지만 **학습 목적함수는 flow matching** |
| 5 | "좋은 행동을 하면 좋은 보상으로 이루어지지 않는다" | 의미가 뒤집혀 있음. **좋은 행동이 항상 즉시 보상으로 돌아오지는 않는다**(지연 보상 / credit assignment)가 정확한 서술 |
| 6 | "정책도 보상을 받을 때마다 **증가**" | 정책은 증가하는 게 아니라 **갱신(update)** 된다. 보상 신호로 파라미터를 조정하는 것 |

### 미확인 (추정하지 않고 남겨둠)

- GR00T 데이터 피라미드의 **정량적 비율** — 정성적 서술만 존재
- π0-FAST 추론 지연의 **구체적 수치** — "significantly slower"라는 정성 서술만
- π0.6 / π0.7 **가중치 공개 여부**
- BeyondMimic **학회 게재처** (arXiv 프리프린트만 확인)
- RT-H **게재 학회**
- ACT temporal ensembling의 **m 값** — 논문 미기재, 공식 코드는 0.01

## 11. 오늘 잡힌 큰 그림

오늘 배운 모델들을 하나의 흐름으로 세워보면 이렇게 된다.

```
강화학습          해보고 보상받아 배운다
   │              └─ 벽: 샘플 비효율 / 희소 보상 / 안전
   ▼
모방학습 (BC)     전문가를 따라 한다
   │              └─ 벽: distribution shift, 누적오차 O(T²)
   ├─ DAgger              실행 중 만나는 상태를 훈련에 추가 → O(T)
   ├─ ACT                 행동을 한 개가 아니라 묶음(chunk)으로 예측
   └─ Diffusion Policy    행동 시퀀스를 확률분포로 생성
   │              └─ 벽: 언어 명령을 이해 못 한다
   ▼
VLA               보고 + 듣고 + 움직인다
   ├─ RT-1        로봇 행동을 Transformer로
   ├─ RT-2        웹 지식을 행동으로 (co-fine-tuning)
   ├─ RT-X        여러 로봇의 경험을 하나로 (embodiment 통합)
   ├─ RT-H        task → language motion → action 계층화
   ├─ OpenVLA     공개 7B, RT-2-X(55B)를 능가
   ├─ π0 계열     flow matching으로 고주파 연속 제어 (50Hz)
   └─ GR00T       듀얼 시스템으로 휴머노이드 전신 제어
```

**관통하는 한 문장**: 전부 **"정책(행동 생성기)을 어떻게 더 잘 만들 것인가"** 에 대한 서로 다른 답이다.

**반복해서 나온 설계 원칙 3가지**
1. **한 순간이 아니라 흐름을 예측한다** — action chunk (ACT, Diffusion Policy, π0, GR00T 전부)
2. **느린 생각과 빠른 행동을 분리한다** — RT-H의 계층, Gemini ER↔VLA, GR00T System 2↔1
3. **데이터의 다양성이 규모보다 중요할 때가 많다** — Open X-Embodiment, OpenVLA, GR00T 피라미드

## 12. 회고

**잘된 점**
- 강의를 따라가면서 "이거 지도학습이랑 같은 거 아닌가?", "확률분포를 만드는 거네", "뇌-척추 느낌이네" 같은 **내 언어로 된 연결**을 계속 만들었다. 이 메모들이 나중에 다시 볼 때 제일 도움이 될 것 같다.
- **"설명이 빈약하다"고 스스로 표시해둔 것**이 오늘 정리에서 제일 값어치가 있었다. 그 두 곳(π0 steerable, GR00T 듀얼시스템)을 확인해보니 실제로 한 곳은 **출처 자체가 다른 모델**이었다. 모르는 걸 모른다고 표시해두는 습관이 실제로 오류를 잡아냈다.

**부족했던 점 / 원인**
- 필기가 강의 흐름을 그대로 받아적는 형태라 **모델 간 관계가 정리되지 않았다.** 원인: 실시간으로 듣다 보니 구조를 세울 여유가 없었음. 대책: 다음 이론 수업부터는 여백에 **"이건 어느 계보의 어디쯤"** 만이라도 한 줄 적어두기.
- 논문 이름·연도를 안 적어둬서 나중에 찾기 어려웠다. 대책: **모델 이름이 나오면 연도와 기관만이라도** 같이 적기.

**아직 확인 못 한 것**
- 강화학습 알고리즘의 실제 내부(PPO, SAC 등)는 다루지 않았다. 개념 수준까지만.
- 논문을 직접 읽은 게 아니라 **강의 + 요약 확인** 수준이다.
