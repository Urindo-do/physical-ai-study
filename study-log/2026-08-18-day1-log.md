## 2. 현재 시스템 상태 진단

터미널에서 명령어 3개를 실행해 노트북 상태를 파악했다.

### 2-1. `cat /etc/os-release` — 설치된 OS 확인

| 요소 | 의미 |
|---|---|
| `cat` | concatenate의 줄임말. 파일 내용을 화면에 그대로 출력 |
| `/etc` | 시스템 설정 파일들이 모여 있는 표준 폴더 |
| `os-release` | 현재 설치된 OS의 이름·버전이 기록된 파일 |

**결과**
```
NAME="Ubuntu"
VERSION="20.04.6 LTS (Focal Fossa)"
VERSION_ID="20.04"
```

→ 과제 요구 버전(22.04)이 아닌 **20.04**가 설치되어 있음을 확인.

### 2-2. `df -h` — 디스크 여유 공간 확인

| 요소 | 의미 |
|---|---|
| `df` | disk free. 디스크의 사용량/여유 공간 표시 |
| `-h` | human-readable. 바이트 대신 K/M/G 단위로 표시 |

**결과 (핵심 줄)**
```
Filesystem       Size  Used  Avail  Use%  Mounted on
/dev/nvme0n1p5   491G  452G   15G   97%   /
```

- `Mounted on`이 `/`인 줄 = 우분투 시스템 전체가 설치되어 동작 중인 파티션
- 전체 491GB 중 452GB 사용, **여유 공간은 15GB뿐 (97% 사용)**
- `/dev/loopN` 줄들은 snap 패키지가 쓰는 가상 장치이므로 실제 여유 공간 계산에서 제외

### 2-3. `lsblk` — 디스크/파티션 구조 확인

| 요소 | 의미 |
|---|---|
| `lsblk` | list block devices. 저장장치와 파티션 구조를 트리로 표시 |

**결과**
```
nvme0n1          953.9G  disk          ← 물리 SSD 전체
├─nvme0n1p1        150M  part
├─nvme0n1p2      453.7G  part          ← 마운트 안 됨 (미사용 상태)
├─nvme0n1p3          1M  part
├─nvme0n1p4        513M  part /boot/efi
└─nvme0n1p5      499.5G  part /        ← 현재 Ubuntu 20.04가 동작 중
```

- 들여쓰기(`├─`, `└─`)는 "이 물리 디스크에 속한 파티션"이라는 부모-자식 관계
- `MOUNTPOINT`가 비어 있으면 현재 어디에도 연결되지 않아 사용되지 않는 상태
- **디스크 전체 954GB 중 453.7GB가 미사용** → 공간 자체는 충분

## 3. 판단 및 결정

| 확인된 문제 | 결정 |
|---|---|
| OS 버전이 20.04 (요구: 22.04) | 지도 교원 확인 결과 **20.04 유지** → 재설치 보류 |
| 루트 파티션 여유 15GB | 재설치 대신 snap 정리 등으로 공간 확보 예정 (미완료) |
| 미사용 453.7GB 파티션의 내용 | `sudo file -s /dev/nvme0n1p2`로 확인 예정이었으나, 재설치 보류로 확인 불필요해짐 |

**⚠️ 향후 리스크로 기록해 둘 것**
Ubuntu 20.04를 지원하는 ROS 2 배포판은 **Foxy**인데, Foxy는 **2023년 5월 지원 종료(EOL)**되었다.
과제가 22.04를 요구한 이유는 ROS 2 **Humble**(2027년까지 지원)의 공식 권장 환경이기 때문.
따라서 리눅스 기초 학습 단계에서는 20.04로 문제없으나, ROS 2 · MoveIt · Gazebo 실습 단계에서는
22.04로의 이전이 필요해질 가능성이 높다.

## 4. 오늘 배운 개념

### 4-1. 파티션 (Partition)
하나의 물리 디스크를 여러 개의 독립된 구역으로 나누는 것.
윈도우 파티션을 축소해 빈 공간을 만들고 그 자리에 우분투를 설치하면 **듀얼부팅**이 되며,
부팅할 때마다 어느 OS로 들어갈지 선택할 수 있다.

### 4-2. Linux vs Ubuntu
- **Linux** = 운영체제의 핵심 엔진(커널) 이름
- **Ubuntu** = 그 커널 위에 만들어진 완성형 배포판 중 하나 = 그 자체로 하나의 OS
- 즉 "리눅스에 우분투를 깐다"가 아니라 "우분투(= 리눅스 계열 OS)를 설치한다"가 정확한 표현

### 4-3. 윈도우 vs 리눅스 구조 차이

| | 윈도우 | 리눅스 |
|---|---|---|
| 디스크 표기 | `C:`, `D:` 드라이브 문자 | `/`(루트) 하나 아래에 모두 매달림. 디스크는 특정 폴더에 **마운트**해서 사용 |
| 관리자 권한 | 프로그램 우클릭 → 관리자 권한으로 실행 | 명령어 앞에 `sudo`를 붙여 그때그때 요청 |
| 파일 종류 구분 | 탐색기 아이콘 모양 | 터미널 글자 **색상** (파랑=폴더, 초록=실행파일, 하늘색=심볼릭 링크) |
| 숨김 파일 | 속성으로 지정 | 파일명이 `.`으로 시작 |

### 4-4. 명령어의 기본 구조
```
명령어   옵션   대상
sudo file -s   /dev/nvme0n1p2
```
- **옵션(플래그)**: `-` 로 시작. 명령어의 기본 동작을 바꾸는 스위치. 여러 개를 합쳐 쓸 수 있음 (`ls -la` = `-l` + `-a`)
- **`/dev` 폴더**: 실제 파일이 아니라, 컴퓨터에 연결된 **하드웨어 장치를 파일처럼 다루는 통로**
  - `/dev/nvme0n1` = 물리 SSD 자체, `p2` = 그 디스크의 2번 파티션

### 4-5. loop 장치와 snap
- **loop device**: 파일 하나를 진짜 디스크처럼 마운트해서 쓸 수 있게 해주는 가상 장치
- 우분투의 **snap** 패키지는 앱과 의존성을 하나의 `.snap` 이미지로 묶어 배포하며, 실행 시 loop 장치로 마운트된다
  → `lsblk` 결과에 `loop0` ~ `loop15`가 잔뜩 보였던 이유
- 아나콘다 가상환경과는 다름. 오히려 윈도우에서 `.iso` 파일을 마운트해 가상 CD 드라이브로 쓰는 것에 가깝다
- 이건 특정 사용자가 설치한 흔적이 아니라 **우분투가 기본적으로 쓰는 구조**. snap이 업데이트 후에도 이전 리비전을 남겨두기 때문에 여러 버전이 쌓인다

### 4-6. `.sh` — 쉘 스크립트
- 터미널 명령어들을 여러 줄 모아 저장한 텍스트 파일. 실행하면 위에서부터 순서대로 자동 실행
- 윈도우의 `.bat`(배치 파일)과 같은 역할. `.exe`처럼 컴파일된 바이너리가 아니라 **읽을 수 있는 텍스트**
- 첫 줄 `#!/bin/bash` = 셔뱅(shebang). "이 파일을 bash로 실행하라"는 표시
- 실행 방법
  ```bash
  chmod +x script.sh   # 실행 권한 부여
  ./script.sh          # ./ = "지금 이 폴더의"라는 뜻. 보안상 생략 불가
  ```
- ROS 2 · SDK 설치 시 자주 마주치게 될 형식

### 4-7. `ls` 옵션 비교

| 명령어 | 동작 |
|---|---|
| `ls` | 파일/폴더 이름만 표시 |
| `ls -a` | `-a` = all. `.`으로 시작하는 숨김 파일까지 표시 (`.` = 현재 폴더, `..` = 상위 폴더) |
| `ls -l` | `-l` = long. 권한·소유자·용량·수정일까지 상세 표시 |
| `ls -la` | 위 둘을 합친 것 |

### 4-8. 권한 표기 읽는 법
`ls -l` 결과 맨 앞의 `-rw-rw-r--` 10글자:
- 1번째 글자: 종류 (`-` = 파일, `d` = 폴더)
- 이후 3글자씩 3묶음: **소유자 / 그룹 / 그 외 모두**의 권한
- `r` = 읽기, `w` = 쓰기, `x` = 실행, `-` = 권한 없음
- `chmod a-w 파일` = all에서 write 권한 제거 / `chmod +x 파일` = 실행 권한 추가

## 5. 미해결 과제

### 5-1. 한글 입력이 안 됨 (⚠️ 미해결)
- 증상: `nano` 등에서 한글 입력 불가. 한/영 전환이 동작하지 않음
- 시도한 것: `sudo apt install language-pack-ko ibus-hangul` 설치 → 여전히 안 됨
- 남은 시도 목록
  1. 재부팅 (`sudo reboot`) — 입력기는 로그인 세션이 새로 시작돼야 인식되는 경우가 많음
  2. `im-config -n ibus` 로 기본 입력기 프레임워크를 IBus로 지정 후 재로그인
  3. 설정 → Keyboard → Keyboard Shortcuts에서 입력 소스 전환 단축키 확인
  4. 로그인 화면에서 세션을 **Ubuntu on Xorg**로 변경해 로그인 (Wayland-IBus 호환 문제 가능성)

### 5-2. 루트 파티션 여유 공간 확보 (미착수)
snap의 오래된 리비전을 정리해 15GB뿐인 여유 공간을 늘린다.
```bash
snap list --all                              # disabled 표시된 구버전 확인
sudo snap remove <앱이름> --revision=<번호>   # 특정 리비전만 삭제
sudo snap set system refresh.retain=2        # 앞으로 최대 2개 버전만 유지
```
